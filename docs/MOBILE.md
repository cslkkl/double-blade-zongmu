# 手机端 — 实现说明与验收

单页横版清版动作游戏在手机 / 平板上的运行方式。桌面行为一个字都没改，这一层只在
真设备有触摸硬件、且玩家真的用手指之后才生效。

> **本页是唯一 home**：触屏输入通道、`?touch=` 参数、虚拟键布局约束、真机验收清单。
> **改这里之后要同步**：`js/touch.js` 与 `js/guide.js` 的 `TOUCH_LEGEND`（说明对侧）· [OPERATIONS.md](OPERATIONS.md) 触屏一节。
> **本页被引用**：[../AGENTS.md](../AGENTS.md) 分层索引 · [README.md](README.md) 事实路由表 · [DEPLOY.md](DEPLOY.md) 手机端一节。

## 零、入口在哪

| 入口 | 给谁 | 行为 |
|---|---|---|
| `index.html` | 桌面 | 键盘 / 手柄界面。有触摸硬件的设备自动切触屏档 |
| `mobile.html` | 手机 | 跳到 `index.html?touch=1`，**强制**触屏档 |

`mobile.html` 存在的理由：从主屏图标启动时没有「第一次手指落下」这个事件，
自动判断会等不到，虚拟键永远不出现。强制开关解决这个。

| URL 参数 | 效果 |
|---|---|
| `?touch=1` | 强制触屏档（虚拟键 + 触屏图例 + 竖屏提示） |
| `?touch=0` | 强制桌面档（触摸屏笔记本上想用鼠标玩时用） |

**判「有没有触屏」只看触摸硬件**（`navigator.maxTouchPoints > 0` 或 `ontouchstart`），
**不看 `PointerEvent`** —— 桌面 Chrome / Edge / Firefox 全都支持 PointerEvent，
拿它当判据会让鼠标点一下页面就切进手机版，玩家看到一圈虚拟键凭空冒出来。
`PointerEvent` 的正确用途只是「选哪种事件 API」。

**鼠标与手指靠 `pointerType` 区分**：`mouse` 不算手指（触摸屏笔记本上用鼠标玩
就保持桌面界面），`touch` / `pen` 算。`everTouched` 只有真的来过一个手指事件才置位。

### 脚本版本号

`index.html` 的 script 标签带 `?v=` 版本号。文件名不带 hash，浏览器与 CDN 会
长期缓存 `js/*.js`；玩家拿到旧版 `touch.js` 就会在桌面上看到手机虚拟键（旧版
`available()` 把「支持 PointerEvent」当成「有触屏」），而且刷新几次都改不掉。
**改了 `js/` 就 `node tools/bump-version.mjs --note "说明"`，别手改。**

格式（`<YYYYMMDD><字母>`、日期段是改动当天、四页共用一个令牌）见
[DEPLOY.md](DEPLOY.md) 的「四、缓存版本号」—— **那里是唯一 home，本页不重抄**。

## 二、为什么不用「模拟键盘事件」

最省事的做法是往 `KEYS` 里塞假按键，但那样会顺手把 `Guide` 的设备判定切成键盘 ——
手机玩家会看到「按 F 挥刀」的提示，而屏幕上一个键盘都没有。

所以走**独立输入通道**：`Touch.state(tag)` 返回与 `readPad()` 同形的对象
（`left/right` 是持续量，其余六个是一次性边沿），`update()` 里用 `||` 并进去：

```js
var tch1 = (window.Touch && Touch.state) ? Touch.state("p1") : null;
var in1 = {
  left:  keyDown(...) || pad1.left || (tch1 && tch1.left),
  jump:  keyPressed(...) || pad1.jump || (tch1 && tch1.jump),
  ...
};
```

模块缺席时 `tch1` 是 `null`，`(null && x)` 恒为 `null`，`a || null` 不改变结果 ——
桌面那条路径的表达式结果与改动前完全相同。

## 三、按键布局

### 单人（`mode === "solo"`）

```
   ┌──────────────────────────────────────────────┐
   │                    ❚❚  ?                     │  ← 顶栏（暂停 / 键位）
   │                                              │
   │              游戏画面（#stage 缩放）           │
   │                                              │
   │                     跳        拾              │
   │  ◀  ▶                        刀   技         │
   │                             丢               │
   │                             递               │
   └──────────────────────────────────────────────┘
     左半屏 = 移动簇          右半屏 = 动作簇
```

### 双人（`mode === "duo"`）

每人独占一半。**动作簇不镜像**、移动簇镜像：

- p1 左半屏：`◀ ▶` 贴屏幕左边缘，`刀` 靠外、`技` 更靠外
- p2 右半屏：`◀ ▶` 贴屏幕右边缘（左右方向反转），`刀` 同样靠外

这样两个玩家「刀」都在自己那一半的外侧、「技」都在更外侧 —— 手感镜像、
功能顺序一致，拇指不用学两套动作。

### 坐标口径（踩过的坑）

| 轴 | 单位 | 为什么 |
|---|---|---|
| x | 相对**本半屏宽度**的百分比 | 半屏是固定的一半视口，百分比在任何屏幕上都是同一比例 |
| y | **按钮直径**的倍数（0.5 = 半个直径） | 用 `vmin` 百分比会让纵向间距跟屏幕高度成比例 |

**y 轴不能用 `vmin`。** 第一版用 `vmin`，在 844×390 的横屏手机上实测：`跳` 飘到
左上角、`拾` 压在角色脸上、`技` 盖住游戏画面正中。改用直径作单位后，
按钮多大间距就多大，任何屏幕密度都是同一套手感。

## 四、画面缩放

`fit()` 重写，三件事桌面不用管：

1. **优先读 `visualViewport`**。手机地址栏收起 / 展开会改 `innerHeight`，
   用 `innerHeight` 会在地址栏收起时算出过大的 scale，画面下缘被切掉。
2. **扣掉安全区**。横屏时刘海在左右，不扣的话血条压在刘海里。
   `#wrap` 的 `padding` 用 `env(safe-area-inset-*)`，`fit()` 读它的计算值。
3. **加 `translateZ(0)`**。把 `#stage` 提到独立合成层 —— 加宽后的图层
   重排在中端安卓上是 5~10ms，够掉一半帧。

**canvas 内部分辨率与逻辑分辨率一致，缩放只改 `transform`**。所有绘制坐标、
碰撞盒、判定半径都以逻辑坐标为单位写，把坐标系缩掉是重写不是适配。

### 逻辑视口加宽（2026-10-26）

手机横屏比 16:9 宽很多（844×390 = 2.16:1，安卓常见 20:9），固定 1600 宽
会左右各留一条黑边 —— **实测 17.9~20% 的屏幕宽度是空的**。所以：

- `W` 变成可变量：桌面恒 `BASE_W = 1600`；触屏设备按 `H × 视口宽高比` 加宽，
  上限 `MAX_W = 2100`（覆盖到 21:9 手机），量化到 8px 一档。
- **高度永远 900**。这是关键 —— 角色身高、精灵比例、所有判定距离一个像素都不变，
  加宽只是「多看到一段关卡」。实测 844×390 下缩放仍是 0.4339，与加宽前完全一致。
- 量化到 8px 是因为地址栏收展会高频触发 `fit()`，而每改一次 `W` 都要重设
  `canvas.width`（会清空画布）。8 逻辑像素 ≈ 3.4 物理像素，看不出来。
- **比 16:9 窄的屏幕（iPad 4:3、竖屏）不加宽**，行为与改动前完全一样。

实测填充率：iPhone SE 100% / iPhone 13 99.8% / 安卓 20:9 99.9% / 21:9 99.9%。

### 加宽后各图层怎么处理（这里最容易做错）

**不能靠拉伸，也不能靠裁切** —— 两条路都会当场露馅：

- **远景**（`bg-far`，1599×900）里有个**正圆的太阳**。拉伸到 1944 宽就是
  横向拉 22%，太阳当场变椭圆。所以改成**等比缩放**：按宽度算统一系数，
  高度跟着长，再把「图里的地平线」对齐到 `GROUND`，多出来的部分是图顶的天空、
  被画布裁掉（看不见）。1600 宽时系数是 1600/1599 ≈ 1.0006、偏移 ≈ 0，
  与改动前逐像素一致。太阳光晕的圆心与半径也要一起乘这个系数，否则会和太阳错开。
- **中景**（`bg-mid`，1600×641）**必须保持素材原尺寸平铺**。试过等比放大：
  加宽到 1944 时要放大 1.215 倍，高度从 641 涨到 779，贴地面线后就顶到画外 ——
  **天空整块被吃掉、青铜柱变粗 21%、编钟横梁被裁断**，画面立刻变闷（已截图对比）。
  原尺寸 + 交替镜像平铺则结构物大小与角色比例永远不变，多出来的宽度读作
  「建筑群继续延伸」。
- **地面**（`ground`，1672×211）本来就是等比平铺，不用动。

## 五、竖屏与「默认横屏」

竖屏时 1600×900 被压成一条窄带（scale ≈ 0.24），角色只有 43px 高。
这种情况由整屏遮罩接管：

- 遮罩**独立于按键层**（`#tch-layer.tch-portrait` 强制 `display:block`），
  标题页、结算页竖着进来也会提示
- 遮罩亮着时虚拟按键全部藏起来（窄带里没有意义，还会误触）
- 图标是一台竖着的手机，自己转 90 度 —— 用图形演示比文字快

### 默认横屏：三条腿

竖屏遮罩只是兜底。真正让手机**进游戏就横过来**的是三条腿，
少一条就有一整片机型转不过来：

| # | 手段 | 管谁 | 说明 |
|---|---|---|---|
| 1 | `<meta name="x5-orientation" content="landscape">`<br>`<meta name="screen-orientation" content="landscape">` | 微信 / QQ / UC 的 X5 内核、部分国产 ROM 浏览器 | 这两条是**私有 meta**，标准里没有，但国产内核只认它们 —— 标准 API 在那些内核里不可用 |
| 2 | `js/touch.js` 的 `lockLandscape()` | 安卓 Chrome / Edge 等标准浏览器 | `requestFullscreen()` 之后 `screen.orientation.lock("landscape")` |
| 3 | 竖屏遮罩 + 「横屏进入」按钮 | iOS Safari、以及上面两条都失败的场合 | iOS **完全没有** `screen.orientation.lock`，只能玩家手动转屏 |

`requestFullscreen()` **必须在用户手势的同步调用栈里**，所以 `lockLandscape()`
挂在两处：

- 「第一根手指落下」（`armFirstTouch` 的 `kick`，全页最早的可靠手势）
- 遮罩里的「横屏进入」按钮（明确的用户意图，且 `force` 绕过「只试一次」的闸）

脚本加载时直接调 100% 被浏览器拒，还会刷一屏 `Uncaught (in promise)`；
所以全部 `.catch` 静默 —— 锁不了方向是正常结果，不是错误，更不能白屏。

`index.html` 与 `mobile.html` 都带这四条 meta（`x5-fullscreen` / `full-screen`
一起给，X5 内核下全屏也要它才生效）。

### 双击放大：只能靠 JS 掐

玩家报告「有些浏览器双击会放大」。这是三件互不覆盖的事，一层都不能省：

| 层 | 手段 | 覆盖谁 | 为什么可能不够 |
|---|---|---|---|
| meta | `maximum-scale=1, user-scalable=no` | 安卓 Chrome、Safari、大部分国产浏览器 | 老 WebView 与部分 ROM 浏览器直接忽略 |
| CSS | `html,body{touch-action:none}` | 支持 CSS `touch-action` 的内核 | iOS 因为可达性原因曾长期不完整支持；且它对「整页捏合」无效 |
| JS | `touchend` 双击守卫 + `gesturestart` | **所有内核** | —— 这是唯一吃得下的那一道 |

双击守卫的判定：**单指 + 两次抬手间隔 ≤320ms + 落点漂移 ≤30px**，
命中时对第二次抬手 `preventDefault()`，顺带吞掉它合成的那一下 `click`
（否则一个双击会把按钮激活两次）。

**为什么不在 `touchstart` 上拦**：一局里同时两根手指是**正常玩法**
（双人同屏、单人两只拇指同时按方向与刀）。在 `touchstart` 上
`preventDefault()` 会连带把 `pointerdown` 一起吞掉，而虚拟键全挂在
pointer 事件上 —— 按键会当场失灵。所以多指一律原样放过：

```js
if (!e.changedTouches || e.changedTouches.length !== 1) { lastAt = 0; return; }
if (e.touches && e.touches.length > 0) { lastAt = 0; return; }
```

iOS 的「整页」双指缩放走的是 `gesturestart` / `gesturechange` / `gestureend`，
不吃 `touch-action`，单独吞掉。

## 六、按键层为什么挂在 `#stage` 外面

`#stage` 是 1600×900 逻辑坐标，手机上被 `transform:scale(0.43)` 缩过。
按键如果放进 `#stage`，100px 的按钮到屏幕上只剩 43px，手指按不准。
而 44px 是 Apple HIG 与 Material 都写进规范的最小触摸目标。

所以按键层 `position:fixed` 贴视口，尺寸用 `vmin` 算并夹在 `[48px, 84px]`。

## 七、指针卡死的三道兜底

手机上和桌面最大的不同：`pointerup` 会**丢**。手指滑出屏幕边缘、来电、
系统通知、切 App、锁屏 —— 都会让 up 收不到。一旦丢了，那枚键就永远「按着」，
玩家看到的是「角色自己一直往前跑，松手也不停」。

三道防线：

1. **`reapStale()`** —— 一次性键（跳 / 刀 / 技 / 拾 / 丢 / 递）按住超过 8 秒
   强制释放。方向键不做这个，因为「按住往前跑」是正常玩法。
2. **`pointercancel` / `pointerleave`** —— 浏览器主动通知时立刻松手。
3. **`blur` / `pagehide` / `visibilitychange`** —— 失焦、切后台、锁屏时 `clearAll()`。

## 十、按键美术：青铜盘 + 金线纹样 + 攻击键跟随武器

布局与输入通道一个字都没改，这一节只讲**键面画的是什么**。

### 三层结构

| 层 | 素材 | 画什么 | 职责 |
|---|---|---|---|
| 底 | `assets/touch/plate.webp`（正圆）<br>`assets/touch/plate-sq.webp`（圆角方盘） | 深青绿锈盘面 + 外圈金色云雷纹，**中心留空** | 唯一的「实体」，承载按键边界感 |
| 中 | `assets/touch/glyph-<field>.webp` 8 张 | 暗刻金线纹样，**低不透明度**压在文字下面 | 只给铸造质感，**不承担识别** |
| 上 | 原有文字标签 | `◀ ▶ 跳 刀 技 拾 丢 递 ❚❚ ?` | 最终识别兜底 |

八个纹样的语义：`left` / `right` 青铜箭头、`jump` 太阳神鸟、`atk` 青铜钺、
`skill` 太阳轮、`act` 玉璧、`drop` 落箭 + 羽、`give` 双面具。

### 为什么文字必须留着

按键直径被 `vmin` 夹在 `[48px, 84px]`（见第六节），小屏横屏上就是 48px。
在这个尺寸上，纯图形对「跳 / 技 / 拾」三者的辨识度不够 —— 三个都是单字概念，
画成纹样之后区分度还不如一个字。所以纹样只做暗刻、低不透明度压在下面，
**文字照旧显示在最上层**。这一层没有降级分支，因为它就是降级本身。

### 为什么两种盘

| 盘 | 给谁 | 形态 |
|---|---|---|
| `plate`（正圆） | 全部动作键 `.tch-b` | 与圆形按钮同一轮廓，盘沿正好贴住按钮边 |
| `plate-sq`（圆角方盘） | 走键 `.tch-b.dir`（`◀ ▶`） | `border-radius:26%`，与动作键在形态上分开 |

盘图本身按 `104.17%` 绘制（= `1 / 0.96`，因为素材把盘体画在画布的 0.96 上），
居中压在按钮上，所以盘沿刚好落在按钮边缘。圆角跟着按钮的 `border-radius` 走
（动作键 50%、走键 26%）—— 方向键与动作键在屏幕上离得近，形态一致会读成
「一排同样的键」，分开之后「左边那对是走、右边那堆是打」不用看字。

### 为什么纹样是低不透明度

纹样的 `opacity` 是 `.52`，目的是让它永远**打不过**文字：

- 纹样压在上面会盖住文字，尤其 `拾` / `递` 这种笔画多的字；
- 金色在深青绿盘上对比度高，全不透明度会变成「金块 + 暗字」，字反而先糊；
- 纹样只是「这块铜上铸过东西」的暗示，看一眼有质感就够，不需要看清是什么。

**这个数是截图调出来的，不是拍的**：`.44` 在 844×390 真机视口上压在青绿盘面里
几乎看不见（等于白做一层素材），`1.0` 又会跟文字抢读；`.52` 是「看得出是铸造纹样、
又读得清字」的那一档。判据是同一个视口下 1× 与 2× 放大各看一次 ——
只看放大图会高估可读性。

### 攻击键跟随手上武器

持械时攻击键（`刀`）的键面直接显示**当前武器图标**：

- 复用 `assets/icons/wp-*.webp` / `it-*.webp` 既有 10 张素材，**零新增图**；
- 武器 → 图标键的映射就是 `index.html` 的 `WP_ICON` / `wpIconKey()`（`short→wpShort`、
  `axe→wpAxe`、`blade→itJade` 等 11 把），路径从 `Assets.MANIFEST` 取 ——
  不在 `js/touch.js` 里抄第二份表；
- 空手、或图标还没解码完时，退回「金线 `atk` 纹样 + 刀字」；
- 挂上武器图标时，`atk` 纹样与「刀」字同时让位 —— 键面就是武器本身；
- 图标各家留白不同（`wp-*` 内容占画布 0.859，`it-rock` 只有 0.411），所以每把武器
  一个缩放比，否则同尺寸下石片、玉器会比刀斧小一大圈。

理由：手机上最常按的就是这枚键，键面直接给出「我现在拿的是什么」比翻 HUD 快；
而且它把「武器换手」这件在手机上完全没有提示的事变成了可见反馈。

**连带改了 `js/guide.js` 的 `TOUCH_LEGEND` 一行**：键位说明里「刀」那条现在写作
「挥刀 · 连按三连击（持械时键面换成手上武器）」。原因是这一层原本的契约是
「文案说按『拾』，屏幕上就真有『拾』」，而攻击键是唯一的例外 —— 持械时它上面没有字。
不写这一句，玩家照图例去找一个写着「刀」的钮会找不到。

### 尺寸口径：每键一个 CSS 变量

三层图的尺寸都写成「相对按钮自身宽高的百分比」，所以 `big`（1.22 倍）/ `sm`（0.74 倍）/
`dir` 三种键自动同比例，不用为每种尺寸再算一遍。每枚键两个变量：

| 变量 | 管什么 | 怎么定 |
|---|---|---|
| `--art` | 纹样的视觉大小 | 按「纹样视觉长边 ÷ 按钮直径」定档：方向键与跳 `0.60`、刀 `0.62`、技 / 拾 `0.56`、丢 / 递 `0.50` |
| `--wpart` | 攻击键上武器图标的大小 | 目标视觉长边 `0.62`，再按该图**内容占画布的比例**换算（见下） |

- **`--art` 的档位是并排看出来的**：0.72 往上纹样会跟文字撞成一团，0.50~0.64 才读成
  「暗刻在盘底的纹」而不是第二层字。小键（丢 / 递）压到 0.50，最大的刀给 0.62。
- **`--wpart` 必须逐张换算，不能一律同尺寸**：图标素材留白各不相同 ——
  `wp-*` 六张统一 0.859，`it-jade` 0.615、`it-bell` 0.583、`it-jar` 0.490、`it-rock` 0.411。
  直接同尺寸塞进去，玉器 / 陶罐 / 石片会比刀斧小一大圈（**这正是踩过的坑**）。
  注意 `MANIFEST` 里 `wpRock` 指向 `it-rock.webp`（同一张图），所以 `wpRock` 要按 0.411 算。
  换算公式就是 `图标显示宽 = 0.62 ÷ 内容占比`，留白大的图会被放大但透明画布不吃像素，
  落地后内容正好跟刀斧一样大。
- **`0.62` 是上限，不能再往上**：盘的内面只有按钮的约 `0.78`，「眼形石」这类**近方形**
  图标按长边 `0.72` 归一后几乎吃满内面、压住盘沿的金色云雷纹，读成一坨石头糊在键上
  （844×390 截图对照过）。长条形的刀斧在 `0.72` 下本来没问题，但两者只能共用一个数 ——
  取小的那个，让方形图标留出边框。

### 降级链（三层各自独立）

| 缺什么 | 退回什么 | 不许发生 |
|---|---|---|
| 盘（`plate` / `plate-sq`） | 原有的径向渐变圆钮（纯 CSS） | 按钮变透明 / 白屏 |
| 纹样（`glyph-*`） | 不画纹样，文字与盘照旧 | 整键退回纯 CSS（盘还在就还画盘） |
| 武器图标 | 「`atk` 纹样 + 刀字」（空手表现） | 键面留空 / 显示裂图 |

三层分别判，不是「一层缺就整键降级」。这条与根 [AGENTS.md](../AGENTS.md) 的硬约束
「每层素材必须有纯代码降级」同源。

### 素材清单与体积口径

| 文件 | 画布 | 内容占比（契约） | 实测（含暗边的 alpha 包围盒） |
|---|---|---|---|
| `plate.webp` / `plate-sq.webp` | 256×256 | 盘体 **0.96** | 248×251 → **0.980**、251×253 → **0.988** |
| `glyph-{left,right,jump,atk,skill,act,drop,give}.webp`（8 张） | 256×256 | 长边 **0.70**（= 179） | **0.699**，几何中心 (0.498, 0.498) |

- 盘的两组数不是矛盾：契约 0.96 是**盘体实心区**，实测更大是因为把烘死在图里的暗边
  算进了 alpha 包围盒。渲染按契约 0.96 铺（`104.17%`），所以盘沿会溢出按钮边约 2%
  （60px 的键上约 1.2px），观感是「盘压住按钮边」，不是缺陷。
- **这 10 张不进 `js/assets.js` 的 `MANIFEST`**。启动期静态图预算已经用满
  （41 键 / 40 条路径），而虚拟键只在真触屏上出现 —— 塞进清单等于让桌面玩家
  白等 10 次解码。改由 `js/touch.js` 自建 Image 缓存，`available()` 为真时才加载。
- 归一化取「盘体实心区包围盒」而不是含暗影的 alpha 包围盒：盘底下缘留着那圈
  柔和暗影当接触阴影，按 alpha 框归一会被暗影撑大一圈、盘体跟着缩小。
- 生成链路：生图两张源图 → `tools/prep_touch.py`（抠洋红 + 切片 + 归一）→
  `assets/touch/` 10 张。详见 [../tools/README.md](../tools/README.md)。
- 因为不进 `MANIFEST`，`showcase.js` 的界面 tab 得手写一份清单才能展出它们
  （浏览器不能列目录）；该清单在 `showcase.js` 的 `TOUCH` 表。
