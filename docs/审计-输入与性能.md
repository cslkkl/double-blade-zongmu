### BUG-输入-01 旋风斩期间照样被打，文案承诺的「1.5 秒无敌」是假的
- 玩家视角：能量条攒满，屏幕上能量条发光闪烁，玩家按 B（或攻击+跳）放出旋风斩，人物开始转圈。**转到一半被小兵一刀砍中，掉血、白闪、受击音全来。** HUD 上明明写着「旋风斩 · 能量满时」，README 与《操作与录屏说明》都写「1.5 秒无敌」。玩家读到的是「这个技能是假的」。
- 位置：`index.html:1520-1521` `updatePlayer`；`index.html:2279-2283` `updateEnemy` 的 `strike` 分支
- 根因：
  1. 发动处只写了三个字段：`p.whirlT = 1.5; p.whirlTick = 0; p.energy = 0;` —— **没有写 `p.inv`**。
  2. 敌人的命中判定只看 `p.inv`：`if(!p||p.dead||p.inv>0) return;` —— 旋风斩期间 `p.inv` 仍是 0，所以照打。
  3. `whirlT > 0` 时 `updatePlayer` 在行 1469 直接 `return`，所以**连击退位移都被吃掉**（下一帧 `p.y = GROUND; p.vy = 0` 把 `vy = -320` 抹掉），但 `p.hp -= e.dmg` 已经扣了。视觉上是「站着不动却掉血」。
- 修改方案：在行 1521 那一句里补上无敌帧，与 `whirlT` 同寿：
  ```js
  p.whirlT = 1.5; p.whirlTick = 0; p.energy = 0;
  p.inv = Math.max(p.inv, 1.5);      // ← 新增：与 whirlT 同寿，兑现「1.5 秒无敌」
  ```
  并在 `updatePlayer` 顶部（行 1447 `if(p.inv>0) p.inv -= dt;`）保持原样 —— 递减已经在跑，不需要第二处。
  验证判据：放旋风斩后连按 Esc 看 HUD 不掉血；或在 `updateEnemy` 的 strike 分支临时 `console.log(p.inv)`，旋风斩 1.5s 内应恒 > 0。
- 严重度：**致命**

### BUG-输入-02 结算页的键盘「任意键」没有闸，玩家最后一刀还在手上就把页面顶掉了
- 玩家视角：玩家一血量见底，正在按住 `D` 往右跑、或正按着 `F` 连砍。两人同时倒下 → 失败页淡入的**同一帧**，因为手指还按在 `D` 或 `F` 上，`restartAll()` 立刻触发。玩家根本没看清「两人都倒下了」，画面已经重开。手柄那边精心做了「启用闸 + 0.4 秒停留」两道闸，键盘这边一道都没有。
- 位置：`index.html:610-611` `keydown` 监听器
  ```js
  if(G.phase==="title") openModeSelect();
  else if(!uiOwned && (G.phase==="win" || G.phase==="lose")) restartAll();
  ```
- 根因：`uiOwned` 只排除了 `KeyH / Escape / KeyM` 三个「归别人的键」。其余**所有**键（`KeyA` `KeyD` `KeyW` `KeyF` `KeyJ` `ArrowLeft` `Slash` …）都会走 `restartAll()`。而 `keydown` 是「按下即触发」，没有「先见到一次全部松开」的闸，也没有 `CONFIRM_ARM` 那种停留时长。这与 `padConfirmEdge()`（`index.html:1276-1286`）的两道闸完全不对等。
- 修改方案：把键盘这条腿也接进同一个闸，别在 `keydown` 里直接 `restartAll()`：
  1. 删掉行 611 的 `restartAll()`，改为只置一个「键盘确认请求」标记：
     ```js
     else if(!uiOwned && (G.phase==="win" || G.phase==="lose")) KEYS.__confirmReq = true;
     ```
  2. 在 `update()` 的结算分支（行 2458 附近，`if(confirmT >= CONFIRM_ARM && padConfirmEdge())` 那一行）扩成三路或：
     ```js
     var kbConfirm = KEYS.__confirmReq && !keyDown(["KeyA","KeyD","KeyW","KeyF","KeyJ",
                        "ArrowLeft","ArrowRight","ArrowUp","Slash","Numpad0","KeyK","Space"]);
     if(confirmT >= CONFIRM_ARM && (padConfirmEdge() || kbConfirm)){
       KEYS.__confirmReq = false;
       ...
     }
     ```
     更稳的做法：新增 `uiKbSeenUp`，与 `uiPadSeenUp` 同构 —— 结算页起来后必须先见到「所有动作键都松开」的一帧才接受。
  3. `showOv()` 里调 `resetConfirm()` 时一并清 `KEYS.__confirmReq`。
  验证判据：结算页出现的瞬间按住 `F` 不放，页面必须停住；松开再按才重开。
- 严重度：**致命**

### BUG-输入-03 手机上一进模式选择页，虚拟按键就盖在页面上，而且按什么都没反应
- 玩家视角：手机横屏打开游戏，手指点了「选择模式 · 开打」→ 模式选择页淡入。**同时屏幕下方浮出一整套虚拟圆钮，压在选择页上面**，还挡住了半屏。玩家按「刀」想确认，没反应；按「▶」，没反应。只能去点页面上那个小小的按钮。
- 位置：`js/touch.js:634-664` `active()` / `tick()`；`index.html:4116` `loop`（`Touch.tick()` 唯一每帧入口）
- 根因：
  1. `active()` 的三个条件是「有触屏 + `everTouched` + 没插手柄」。`everTouched` 由 `armFirstTouch()` 在**全局捕获阶段**的 `pointerdown` 置真（`touch.js:709`）——玩家点标题页按钮那一下就满足了。所以模式选择页必然显示虚拟键。
  2. `tick()` 只切 `tch-on` / `tch-intro` 两个 class，**没有任何「当前是哪个覆盖层」的概念**。
  3. 虚拟键的输入只在 `update()` 的 `play` 分支被读（`index.html:2318-2319`）。`G.phase === "title"` 时读的是 `anyPress()`（`index.html:2466-2474`），它只扫 `KEYS` 与 `PADS`，**完全不看 `Touch.state()`**。
  4. `#tch-layer` 是 `z-index:70`（`touch.js:123`），模式选择层是 `z-index:60`（`ui-shell.js:58`）→ 虚拟键压在上面。
- 修改方案：
  1. `Touch` 新增 `gated()`：只在「`G.phase === "play"` 且 `!G.paused` 且 `!G.intro`」时返回 true；`tick()` 用 `want = active() && gated()`。
  2. `anyPress()`（`index.html:2466`）末尾补一条触屏分支，让手机能按键进模式页：
     ```js
     if(window.Touch && Touch.state){
       var t = Touch.state("p1");
       if(t.atk || t.jump || t.act || t.skill) return true;
     }
     ```
  3. 结算页同理（见 BUG-输入-12）。
  4. 把 `#tch-layer` 的 `z-index` 从 70 降到 55（低于 ui-shell 的 60），这样即使将来漏了闸，覆盖层也永远在虚拟键之上。
  验证判据：手机上点标题页按钮 → 模式选择页出现时 `document.getElementById("tch-layer").classList.contains("tch-on")` 必须为 `false`；进对局后为 `true`。
- 严重度：**致命**

### BUG-输入-05 暂停页对手柄没有「先松开一次」的闸，按着 A 时按 Esc 会瞬间解冻
- 玩家视角：一手键盘按 `Esc` 暂停、另一手手柄还按着 `A`（上一刀刚挥出去）。暂停页刚出现就自己消失了，玩家连「暂停」两个字都没看见。
- 位置：`index.html:1076-1089` `updatePaused`；`index.html:1038` `stopPadEdge()`
- 根因：进暂停时 `stopPadEdge()` 把 `padPrev = {}` 清空。`padEdge`（行 642）在 `padPrev[k]` 为空时看到 `v === true` 就**判为上升沿**：
  ```js
  function padEdge(k,v){ if(v&&!padPrev[k]){padPrev[k]=true;return true;} ... }
  ```
  所以「清空 prev」并不等于「设闸」，反而把「本来就按着」变成了一次假上升沿。`padConfirmEdge()`（行 1276）用 `uiPadSeenUp` 做真闸，暂停页没有对应机制。
- 修改方案：给 `updatePaused` 加一份与 `padConfirmEdge` 同构的闸：
  ```js
  var pzSeenUp = false;      // 暂停页起来后是否见过一次全松开
  // togglePause(true) 里：pzSeenUp = false;（与 stopPadEdge() 并列）
  // updatePaused 里：
  var heldAny = btn(9) || btn(0) || btn(1) || btn(3);
  if(!heldAny) pzSeenUp = true;
  if(pzSeenUp){ ...原有的 padEdge 三条... }
  ```
  注意 `btn` 是 `updatePaused` 内部的闭包，`heldAny` 要放在 `if(gp){...}` 内。
- 验证判据：按住手柄 A 不放，键盘按 Esc 进暂停，暂停页必须停住 ≥ 0.5s。
- 严重度：**高**

### BUG-输入-06 连击会「丢键」：收招的 0.16 秒里按下的攻击被彻底吃掉
- 玩家视角：玩家连按 `F` 想打三连击。前两下很顺，第三下**没出来**，角色站着发愣。再按一下才动。玩家读到的是「连击不跟手 / 有时按了没反应」。
- 位置：`index.html:1549-1557` `updatePlayer`
  ```js
  if(inp.atk && canAct && p.swingCd<=0){ ... startSwing(p, 0); }
  else if(inp.atk && p.swingT>0){ p.swingQueued = true; }
  ```
- 根因：`inp.atk` 是**边沿量**（键盘走 `keyPressed` 取走即清；手柄走 `padEdge` 置 `padPrev`）。分支只覆盖两种状态：
  - `p.swingCd > 0`（上一段收招的 0.16 秒，行 1578 `p.swingCd = 0.16;`）→ 第一个条件假；
  - `p.swingT <= 0`（已经收完）→ 第二个条件也假。
  两个都不成立时，**这次边沿已经被 `keyPressed` / `padEdge` 消费掉了，永远不会再来一次**。0.16 秒的窗口在 60fps 下是 9~10 帧，玩家「稍快一点」就掉进去。三连击的手感问题主要来自这里。
- 修改方案：把「收招期间按下的攻击」也记进队列，而不是丢掉：
  ```js
  if(inp.atk && p.swingT<=0 && p.swingCd>0){
    p.swingQueued = true;            // ← 新增：收招窗口内的输入记下来，别吃
  }
  ```
  放在行 1555 的 `else if` **之前**。同时把 `swingT<=0` 且 `swingCd<=0` 时的消费逻辑保持原样（行 1566-1577 已能处理 `swingQueued`）。
  另一条更彻底的路：把 `p.swingCd` 从 0.16 降到 0.08，并把 `swingQueued` 改成「最多缓存 0.12 秒」的时间戳队列（`p.atkBufT`），超时丢弃。后者对手感提升更大，但改动面也更宽 —— 建议先做前者，A/B 对比手感。
- 验证判据：写一个 3 行脚本按固定 180ms 间隔发 `keydown`/`keyup`（`F`），数 `p.swingIdx` 到达 2 的次数；改前应能看到大量只到 1 就停。
- 严重度：**高**

### BUG-输入-10 双人触屏模式下每半屏塞 8 个键，主攻击键与拾取键互相重叠
- 玩家视角：手机上开双人，屏幕右半边同时出现 p2 的「◀ ▶ 跳」和「刀 技 拾 丢 递」共 8 个圆钮。拇指想按「刀」，实际常常按到「拾」（变成捡东西而不是挥刀），或者两个键一起触发。玩家读到的是「手机上按刀在捡东西」。
- 位置：`js/touch.js:270-277` `layoutFor`、`:232-252` `moveCluster` / `actCluster`、`:414-421` `place`
- 根因（**可测量判据**）：duo 模式下 `layoutFor` 返回 `moveCluster(mirror).concat(actCluster(mirror))` —— **8 个键全挤在 50% 视口宽里**。`actCluster` 的 x 是半屏百分比：`atk 60`、`skill 82`、`act 44`、`drop 68`、`give 88`。以 iPhone 横屏 844px 为例，半屏 422px：

### BUG-输入-14 粒子没有上限，最坏一帧能堆到上千个 fillRect

  ```js
  // 行 2305 之前先记一份真实 dt

  if(G.hitstop > 0){ G.hitstop -= dt; dt *= 0.08; }
  ...
  if(G.phase === "play"){ G.time += dtReal; ... }   // ← 用真实 dt
  ```

### BUG-输入-21 canvas 内部分辨率固定 1600×900，高 DPI 屏上画面发虚
- 玩家视角：MacBook / 手机（DPR 2~3）上，文字与描边明显糊，尤其 HUD 上的「耐 18 / 18」和掉落物名字。
- 位置：`index.html:263`（`<canvas id="cv" width="1600" height="900">`）、`index.html:399` 附近 `fit()`
- 根因：`fit()` 只改 `#stage` 的 CSS `transform: scale(s)`，canvas 的 backing store 恒为 1600×900。DPR=2 的屏幕上 1 个 canvas 像素被拉到 2×2 物理像素 → 双线性放大 → 模糊。
- 修改方案：给 `fit()` 加 DPR 感知（注意会 **×4 填充率**，移动端要设上限）：
  ```js
  var DPR = Math.min(window.devicePixelRatio || 1, 2);   // 上限 2，移动端别上 3
  cv.width  = Math.round(W * DPR);
  cv.height = Math.round(H * DPR);
  cv.style.width  = W + "px";
  cv.style.height = H + "px";
  ctx.setTransform(DPR, 0, 0, DPR, 0, 0);
  ```
  但 `render()` 首行有 `ctx.setTransform(1,0,0,1,0,0)`（行 3997），会把 DPR 缩放抹掉 —— 必须同步改成 `ctx.setTransform(DPR,0,0,DPR,0,0)`，并把 `W`/`H` 保持为逻辑值。
  **这条改动与性能直接冲突**（填充率 ×4），建议只在 `DPR >= 1.5 且视口面积 < 1920×1080` 时启用，并在改动前用 `perf` 测一帧时间。
- 严重度：**中**
