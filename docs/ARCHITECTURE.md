# 双刃战士 · 纵目 — 架构说明

本文只写**不变的设计决策**。
「有哪些文件、怎么改」在 [../js/README.md](../js/README.md) 与 [../tools/README.md](../tools/README.md)。

## 不可破坏的约束

- 零外部依赖：无 CDN、无 npm、无外部字体、无网络请求。
- `file://` 双击 `index.html` 必须能完整游玩。
- 参赛现场断网运行，这是评审硬规则，不是工程偏好。
- 逻辑分辨率固定 1600×900，`#stage` 用 `transform: scale()` 等比缩放到窗口。
- 地面线 `GROUND = 706`、世界宽 `WORLD_W = 3400` 是所有坐标的基准，改动等于重做关卡。

## 为什么不用 Phaser / 任何引擎

- 引擎产物要么带 runtime 文件，要么要求 http 服务，两者都破坏「单目录、断网、双击即玩」。
- 引擎的资源和渲染管线会引入版本锁定，评审机器无法保证环境一致。
- 本作只需要 Canvas 2D 的绘制原语、`requestAnimationFrame` 和 Web Audio，原生 API 已足够。
- 代价是自己实现相机、碰撞、动画播放、资源加载；收益是零安装、零版本风险。
- 结论：引擎带来的抽象收益低于它带来的分发风险，不用。

## 为什么不用 ES module

- `file://` 协议下 `type="module"` 的脚本请求被视为跨源，被 CORS 策略拦掉，页面直接白屏。
- 因此全部模块写成 IIFE，执行时把自己挂到 `window.*`，只暴露一个对象。
- 加载顺序由 `index.html` 的 `<script src>` 顺序决定，必须满足依赖方向：数据 → 绘制 → 主循环。
- 跨模块通信只走 `window.XXX` 这一个命名空间，不共享闭包变量。
- 每个模块的对外契约写成函数签名注释，改动契约要同步改调用方的守卫判断。

## 视觉与碰撞分离

- 位图只负责好看；位置、体型、命中判定全部由数字决定。
- 玩家碰撞盒是固定矩形 `x ± 30`、高 150，与角色图 252px 显示高度无关。
- 敌人碰撞盒由 `scale` 推出：`w = 70 × scale`、`h = 160 × scale`，四类敌人只差参数。
- 血条不参与判定，位置由图形高度推出：普通敌人顶边 `e.y - e.h - 22`，BOSS 用帧图时抬到 `e.y - 1.6 × e.h - 22`。
- 改美术只要不动这两组数字，手感就不会变；改数字必须同时检查美术是否穿帮。
- 攻击判定用「挥砍进度 22%~86% 之间持续检测」而不是单帧瞬时检测，避免掉帧漏判。

## 帧数据与绘制解耦

- `anim-data.js` 只放数据：帧数、fps、循环标记、画布尺寸、锚点、`scaleFix`、文件列表。
- 播放与绘制只读数据，不写数据；生成脚本是唯一写入口。
- 好处是重切素材不改一行绘制代码，重做绘制不改一帧素材。
- 播放状态挂在实体对象上（`p.__rig`、`e.__ea`），不放在模块全局，避免两只敌人互相踩帧。
- `attack` 这类必须与判定同步的动作，帧号由 `swingT / swingDur` 推导，不按 fps 自由播放。

## 三级降级策略

- 第一级：逐帧图（`ANIM` / `ENEMY_ANIM` 就绪）。
- 第二级（仅玩家）：单张精灵 `pose0` + 变换动画，用于帧图全挂但底图还在的情况。
- 第三级：纯代码绘制（`drawFighter`、`drawWalker` / `drawBrute` / `drawBoss`、`drawBG`、弧形刀光）。
- 敌人与背景只有两级（帧图/素材 ↔ 纯代码），因为它们的纯代码版本本身就是完整实现。
- 降级是刻意的：素材是加分项，不是运行前提；任何一张图加载失败都不许白屏、不许抛异常。
- 降级判定必须廉价：`ready()` 走缓存布尔量，不做逐帧扫描。
- 绘制热路径禁止 `new Image()`、禁止建 canvas；缓存键由「素材身份 + 尺寸 + 颜色」构成。

## 跨帧对齐约定

- 同一动作的所有帧共用同一张画布尺寸，出图时统一 padding。
- 水平锚点 `anchorX` 取躯干中线（内容高度 50%~70% 区间的不透明像素中位数），剔除刀、环等离群像素。
- 垂直锚点 `footY = 1.0`，即脚底贴画布下沿，绘制时 `dy = -footY × h`，角色永远踩在 `p.y` 上。
- 不做这两件事就一定抖：逐帧看是「脚在原地滑」或「身体左右横跳」。
- `scaleFix` 是补丁不是设计：它修正生图模型给出的条带身高不一致（例如 walk 条带比 idle 小 33%），值等于「目标身高 ÷ 该条带实际身高」。
- 新增动作时先量出该条带的实际身高，再写 `scaleFix`；写死感觉值会让后续换图全崩。

## 素材流水线

- 生图：AI 出图，角色与道具统一用洋红底（`min(R,B)-G` 可量化），场景不用。
- 抠图 + despill：`min(R,B)-G` > 110 硬抠透明，45~115 之间按比例降 alpha，其余把 R/B 压到 `G+34` 以内。
- 分帧：列投影找连续内容段，段数多于帧数时按「间隙 + 中心间距偏差」合并碎片，再对几何边界做局部极小吸附。
- 统一锚点：见上一节，先算全动作的 `maxL / maxR / maxUp`，再一次性铺到共用画布。
- 编码：预乘 alpha 后缩放（避免边缘发黑发紫），再二次 defringe，最后 WebP `quality 90 / alpha_quality 100`。
- 预算：单帧 ≤ 60 KB、总量 ≤ 3 MB；超预算就整批降采样重出，不单独压某几帧。
- 顺序：角色在前、敌人在后；角色脚本会重建 `anim-data.js`，敌人脚本只在末尾追加。

## 渲染顺序

- 背景层（视差 0.20 / 0.50 / 1.00 / 1.30 四档）→ 世界坐标（掉落物、敌人、玩家、刀光、投掷物、粒子、飘字）→ 屏幕坐标（白光、受伤渐晕、阵亡标记）。
- 背景模块只在屏幕坐标系里用相机值算偏移，不做世界坐标平移；调用方负责震屏平移。
- 所有 `save()` / `restore()` 成对，合成模式与 alpha 不允许泄漏到外层。
- 视差系数改一个就够，但要连改两处：素材版背景与纯代码兜底背景用的是两套独立常量（0.10 / 0.38 vs 0.20 / 0.50），这是历史遗留，改前先确认改哪套。

## 输入与手感

- 键盘与手柄走同一条抽象：每个玩家只认 `left / right / jump / atk` 四个布尔量。
- 键盘区分「按下瞬间」与「持续按住」；手柄按钮做边沿检测，摇杆做死区判断。
- 攻击输入在挥砍进行中记为「排队」，当前段结束立刻接下一段，这是三连击成立的前提。
- 命中时插入极短停顿（`hitstop`）并把整体 `dt` 压到 8%，这是打击感的主要来源，不要为了「顺滑」删掉。
- 相机跟随两名玩家的中点并做指数逼近；单人时中点就是玩家一。

## 状态机

- 全局阶段：`title → play → clear → play … → win`，任一玩家全灭则 `lose`。
- 敌人状态：`walk → windup → strike → recover → walk`，受击插入 `hurt`，死亡进入 `dead`。
- `windup` 是玩家的唯一预警窗口，`recover` 是 BOSS 的弱点窗口（受伤 ×2）。
- 状态时长写死在敌人构造与转移处，不放在数据文件里：它属于判定，不属于美术。

## 防错清单

- 新增素材：先确认降级路径仍在，再确认 `ready()` 判定覆盖它。
- 新增动作：`CLIPS` 预热名单 + `pickClip` 优先级 + `scaleFix` 三处都要动。
- 新增敌人类型：`ENEMY_ANIM` 键名、`KINDS` 预热名单、血量/速度/体型参数、纯代码降级分支四处都要动。
- 改 `anim-data.js`：任何生成脚本写完都要 `node --check`，历史上这里出过 `fps: 6, true, loop: true` 的语法错误。
- 改背景：`ready()` 现在判 `complete && naturalWidth > 0`，「加载中」与「加载失败」都会让它为假；两者对外都表现为回落纯代码背景。
- 背景是唯一会在 `draw()` 里二次自检的模块：4 张核心图任一不可用就直接返回 `false` 且一像素不画，调用方据此补 `drawBG()`；道具层失败不进这个判定，由 `drawProps` 逐张剔除。
- 已知取舍：判定放在绘制之前，所以 `draw()` 返回 `false` 时屏幕上不会留下半张素材背景，调用方可以直接补画，不需要再清屏。
