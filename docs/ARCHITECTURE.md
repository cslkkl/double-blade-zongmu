# 双刃战士 · 纵目 — 架构说明

本文只写**不变的设计决策**。
「有哪些文件、怎么改」在 [../js/README.md](../js/README.md) 与 [../tools/README.md](../tools/README.md)。

## 不可破坏的约束

- 零外部依赖：无 CDN、无 npm、无外部字体、无网络请求。
- `file://` 双击 `index.html` 必须能完整游玩。
- 参赛现场断网运行，这是评审硬规则，不是工程偏好。
- 逻辑**高度**固定 900，`#stage` 用 `transform: scale()` 等比缩放到窗口。
- 逻辑**宽度** `W` 可变：桌面恒 1600；触屏设备按视口比例加宽到 `H × 宽高比`，上限 2100。
  只加宽不改高，所以角色身高、精灵比例、所有判定距离一个像素都不变 ——
  加宽等于「多看到一段关卡」，不是拉伸也不是裁切。见 [手机端适配.md](手机端适配.md) 的「逻辑视口加宽」。
- 地面线 `GROUND = 706`、世界宽 `WORLD_W = 3400` 是所有坐标的基准，改动等于重做关卡。

## 为什么不用 Phaser / 任何引擎

- 引擎产物要么带 runtime 文件，要么要求 http 服务，两者都破坏「单目录、断网、双击即玩」。
- 引擎的资源和渲染管线会引入版本锁定，评审机器无法保证环境一致。
- 本作只需要 Canvas 2D 的绘制原语、`requestAnimationFrame` 和 Web Audio，原生 API 已足够。
- 代价是自己实现相机、碰撞、动画播放、资源加载；收益是零安装、零版本风险。
- 结论：引擎带来的抽象收益低于它带来的分发风险，不用。

## 为什么不用 ES module

- `file://` 协议下 `type="module"` 的脚本请求被视为跨源，被 CORS 策略拦掉，页面直接白屏。
- 因此全部模块写成 IIFE，执行时把自己挂到 `window.*`，只暴露一个对象。
- 加载顺序由 `index.html` 的 `<script src>` 顺序决定，必须满足依赖方向：数据 → 绘制 → 主循环。
- 跨模块通信只走 `window.XXX` 这一个命名空间，不共享闭包变量。
- 每个模块的对外契约写成函数签名注释，改动契约要同步改调用方的守卫判断。

## 视觉与碰撞分离

- 位图只负责好看；位置、体型、命中判定全部由数字决定。
- 玩家碰撞盒是固定矩形 `x ± 30`、高 150，与角色图 252px 显示高度无关。
- 敌人碰撞盒由 `scale` 推出：`w = 70 × scale`、`h = 160 × scale`，四类敌人只差参数。
- 血条不参与判定，位置由图形高度推出：普通敌人顶边 `e.y - e.h - 22`，BOSS 用帧图时抬到 `e.y - 1.6 × e.h - 22`。
- 改美术只要不动这两组数字，手感就不会变；改数字必须同时检查美术是否穿帮。
- 攻击判定用「挥砍进度 22%~86% 之间持续检测」而不是单帧瞬时检测，避免掉帧漏判。

## 帧数据与绘制解耦

- `anim-data.js` 只放数据：帧数、fps、循环标记、画布尺寸、锚点、`scaleFix`、文件列表。
- 播放与绘制只读数据，不写数据；生成脚本是唯一写入口。
- 好处是重切素材不改一行绘制代码，重做绘制不改一帧素材。
- 播放状态挂在实体对象上（`p.__rig`、`e.__ea`），不放在模块全局，避免两只敌人互相踩帧。
- `attack` 这类必须与判定同步的动作，帧号由 `swingT / swingDur` 推导，不按 fps 自由播放。

## 三级降级策略

- 第一级：逐帧图（`ANIM` / `ENEMY_ANIM` 就绪）。
- 第二级（仅玩家）：单张精灵 `pose0` + 变换动画，用于帧图全挂但底图还在的情况。
- 第三级：纯代码绘制（`drawFighter`、`drawWalker` / `drawBrute` / `drawBoss`、`drawBG`、弧形刀光）。
- 敌人与背景只有两级（帧图/素材 ↔ 纯代码），因为它们的纯代码版本本身就是完整实现。
- 降级是刻意的：素材是加分项，不是运行前提；任何一张图加载失败都不许白屏、不许抛异常。
- 降级判定必须廉价：`ready()` 走缓存布尔量，不做逐帧扫描。
- 绘制热路径禁止 `new Image()`、禁止建 canvas；缓存键由「素材身份 + 尺寸 + 颜色」构成。

## 跨帧对齐约定

- 同一动作的所有帧共用同一张画布尺寸，出图时统一 padding。
- 水平锚点 `anchorX` 取躯干中线（内容高度 50%~70% 区间的不透明像素中位数），剔除刀、环等离群像素。
- 垂直锚点 `footY = 1.0`，即脚底贴画布下沿，绘制时 `dy = -footY × h`，角色永远踩在 `p.y` 上。
- 不做这两件事就一定抖：逐帧看是「脚在原地滑」或「身体左右横跳」。
- `scaleFix` 是补丁不是设计：它修正生图模型给出的条带身高不一致（例如 walk 条带比 idle 小 33%）。
- 屏幕身高不是 `252 × scaleFix`，而是 `252 × scaleFix × (内容高 ÷ 画布高)`：`scaleFix` 缩放的是整张画布，画布里的空白不吃像素。
- 因此 `scaleFix` 的正确算法是以 idle 为基准反算：`scaleFix = (idle 内容高 ÷ idle 画布高) ÷ (该 clip 内容高 ÷ 该 clip 画布高)`。
- 新动作切片后必须实测内容高（alpha > 24 的包围盒）再填 `scaleFix`；只填 `1.0` 会让该动作比其他动作高出一大截。
- 验收标准：按每 clip 的内容高中位数折算，12 个动作的屏幕身高落在 178~181px，容差 ±2px；超出即 `scaleFix` 写错。

## 图标统一画布

- 生图一次出六个图标，切完每格的透明包围盒各不相同；直接按各自包围盒缩放到目标尺寸，屏幕上就会忽大忽小。
- 解法是切完再归一：裁到内容包围盒 → 统一正方形画布 → 按最长边占固定比例居中，缩放只剩长边一个自由度。
- 尺寸按用途分三档：武器 256、物品 192、界面 128；比例系数 0.86 / 0.84 / 0.88，三档的边框留白观感一致。
- 实测长边占比：武器 0.859（6 张完全一致）、界面 0.875（4 张完全一致）；物品 0.41~0.65，同族内不齐。
- 物品族不齐是已知偏差：脚本设定的占比是 0.84，磁盘上这批物品图的实际占比更低，说明它们不是当前脚本这一版产出的。
- 消费侧只按长边等比缩（掉落物 56px、HUD 24px），不读原始像素尺寸 —— 归一之后原始尺寸不再有意义。

## 素材流水线

- 生图：AI 出图，角色与道具统一用洋红底（`min(R,B)-G` 可量化），场景不用。
- 抠图 + despill：`min(R,B)-G` > 110 硬抠透明，45~115 之间按比例降 alpha，其余把 R/B 压到 `G+34` 以内。
- 分帧：列投影找连续内容段，段数多于帧数时按「间隙 + 中心间距偏差」合并碎片，再对几何边界做局部极小吸附。
- 统一锚点：见上一节，先算全动作的 `maxL / maxR / maxUp`，再一次性铺到共用画布。
- 编码：预乘 alpha 后缩放（避免边缘发黑发紫），再二次 defringe，最后 WebP `quality 90 / alpha_quality 100`。
- 预算：单帧 ≤ 60 KB、总量 ≤ 8 MB；超预算就整批降采样重出，不单独压某几帧。
- 总量预算从 3 MB 改到 8 MB 是跟着「武器视觉」放的，不是松标准：武器从「一套动画配一切」变成每把各有站立帧、单帧出招、四帧序列、专属刀光与材质火花，一次多了 67 张（实测 anim/ 3.7 MB + fx/ 0.36 MB，全仓 5.96 MB，单帧最大 55.4 KB）。判定依据是实机装载：`file://` 下 96 张 `window.IMG` 全部 85 ms，页面零报错 —— 6 MB 在本地加载里不是瓶颈，而砍掉这些图就是砍掉这次的全部效果。**单帧 60 KB 这条没有放宽**，继续卡。
- 顺序：角色在前、敌人在后；角色脚本会重建 `anim-data.js`，敌人脚本只在末尾追加。

## 渲染顺序

- 背景层（视差 0.20 / 0.50 / 1.00 三档）→ 世界坐标（掉落物、敌人、玩家、刀光、投掷物、粒子、飘字）→ 屏幕坐标（白光、受伤渐晕、阵亡标记）。
- 没有「角色之后」的前景层：3 座高大遮挡物（纵目面具浮雕 / 铜鼎 / 神树）曾画在角色之上，已于 2026-10-25 删除，详见下节。
- 背景模块只在屏幕坐标系里用相机值算偏移，不做世界坐标平移；调用方负责震屏平移。
- 所有 `save()` / `restore()` 成对，合成模式与 alpha 不允许泄漏到外层。
- 视差系数改一个就够，但要连改两处：素材版背景与纯代码兜底背景用的是两套独立常量（0.10 / 0.38 vs 0.20 / 0.50），这是历史遗留，改前先确认改哪套。

## 前景遮挡层已删除（2026-10-25）

- 原来 `Background.drawFront()` 在角色之上画 3 座高大遮挡物，角色走过去被完全盖住，只好再加一条「被遮挡时压到 52% alpha」的淡出（`occluders()` 契约 + `p.__alphaMul` 通道）。
- 删掉的理由：淡出是**硬切换**（进出区间瞬间跳变，没有过渡），且判定**只看 x 不看高度**——站在道具旁边就淡。两处叠起来读起来像 bug 而不像遮挡；受击无敌闪烁再乘上去（`0.55 × 0.52`）人几乎看不见。
- 现状：遮挡物退回中景 `PROPS`（`maskRelief` / `brazier` / `sacredTree` 三个键仍在 `PROPS` 与 `PROP_KEYS` 里，素材不浪费），角色任何时候满不透明。
- 契约变化：`Background` 只剩 `draw()` 与 `ready()`；`drawFront()` / `occluders()` 已移除，`index.html` 不再有 `playerOccluded()` 与 `OCC_FADE_ALPHA`。
- `p.__alphaMul` 通道保留在 `char-rig.js` 里（6 处绘制共用），当前无调用方，作为通用 alpha 钩子；要用直接设这个字段，别在外层包 `globalAlpha`（会被绝对覆盖）。

## 武器持有是单手一把

- `p.weapon` 是手上正在用的（可以是空手 `fist`），没有备用格。
- 不设背包的理由：背包把「捡到好武器」变成管理负担 —— 四格里躺着一把更好的，玩家却要按键才知道；单手一把把选择压缩成「走过去换不换」。
- 拾取语义：空手直接上手；手上有别的就换手，旧的那把落回原地（落点与拾取判定半径错开，避免刚放下又被同一把抢回）。
- 丢弃只丢手上那把，回到空手；本来空手只飘字，不改状态。
- 递队友走同一套语义：队友空手就交出去、自己回到空手；队友手上有武器就两人对换，换下来的那把不落地。距离上限 160px，超出只飘字不执行。

## 动作按武器类型分流

- 斧与锤是重武器，走双手劈砍 `attack-heavy`；叉、匕、璋是快武器，走长柄突刺 `attack-thrust`；剑与空手沿用 `attack`。
- 分流的理由是重量感：同一套挥砍帧套在神树锤和骨牙匕上，两者的出手速度差三倍，动作会读成「卡帧」。
- 映射写在 `ATTACK_CLIP`（武器 key → clip 名），只决定 clip 名，不碰帧数据也不碰绘制。
- 传递通道是 `p.__forceClip`：`startSwing()` 挂上，收招时清空；`char-rig` 只在 `swingT > 0` 且该 clip 在数据里真实存在时才采用，否则回落 `attack`。
- 三个攻击 clip 的帧号仍由 `swingT / swingDur` 推导，不按 fps 自由播放 —— 攻击族共用一条时间轴。

## 手上那把刀必须真的换掉

- 光有「武器类型 → 动作种类」不够：`attack` 族那三套帧不管手里拿什么都长同一副样子（都是那两把玉璋刃）。玩家换到手一把钺，砍出来还是玉璋刃 —— 这就是「手上模型不变」的根因。
- 三层修复，缺一层都会露馅：
  1. **拾取即上手**：捡到的武器直接进 `p.weapon`。手上已有别的武器时是换手 —— 旧的那把落回原地，玩家看得见自己换掉了什么。
  2. **站定时换模型**：`window.ANIM_HOLD`（武器 key → 单帧站立）接管 `idle`。走 / 跳 / 受伤 / 旋风 / 死亡仍然用动画，因为那些帧是全身动作、没法只换手里那件东西。
  3. **出招时换模型**：`window.WEAPON_ATTACK`（武器 key → 单帧出招）接管 `attack` 族。它盖在 clip 之前，`__forceClip` 降级成「这把武器没有专属姿态时」的兜底。
- 出招姿态是一张图 + 一条 `swingT` 时间轴，不是帧序列：前 35% 蓄力（后仰），之后前冲并顺向甩开，`swingIdx` 决定距离与角度。判定仍只认 `index.html` 里的数字框，绘制怎么甩都不影响打击范围。
- **单帧只是降级，正式形态是四帧序列**（`WEAPON_ATTACK_CLIP`）：一张图靠旋转拉伸装出来的挥砍，在钺与锤这种大重量动作上一眼就僵。序列的帧号走与 attack 族同一个 `attackFrame()`，所以「有几帧」不影响出手时机 —— 这是它能替换掉动画 clip 而不破坏手感的原因。
- 序列有两个必须守住的字段：`scaleFix` 是**一把武器一个数**（四帧共用同一张画布，逐帧各算会让连击里忽大忽小），`anchorX` 是**逐帧数组**（挥砍时身体轴线前后移，写成一个数会让整个人左右漂）。四帧画布尺寸也必须一致，否则每秒抖四次。
- 三者的键集合必须能对上 `WEAPONS` 的 key。新增武器时同时要动：`ANIM_HOLD`、`WEAPON_ATTACK`、`WEAPON_FX`、`HIT_MATERIAL`（间接）、`audio.js` 的 `MATERIAL`、`index.html` 的 `WP_ICON` 与 `WPN_HIT_MAT`。少一处，那一把武器就会在某个瞬间变回老模型或发错声音。

## 每把武器的特效也要能认出是谁

- 只有一套金色月牙时，六把近战用出来的画面完全一样，跟「动作按武器分流」的努力互相抵消。
- 刀光分两级：`WEAPON_FX[武器 key]`（专属图 + 半径 `r` + 弧张角 `arc`）优先，缺图才落回通用 `slash-1/2/3` 三档，再缺就落回 `drawFallbackSlash` 的纯代码弧光。
- **刀光的朝向是一条契约，不是随手一个镜像开关。** 源画月牙「凸背朝左」（实测：脊线弧心 `cx/w` 在 0.5178~1.0272，全部 > 0.5），玩法要求「凸背朝人面向的方向」，于是**面朝右要镜像、面朝左用原样** —— 与「素材朝右、朝左才镜像」的常规写法相反。判据只有一处：`js/fx.js` 的 `ART_CONVEX` + `slashMirror()`，两条绘制路径共用。旧代码用常规写法，两个朝向都把凸背送进了人背后（左挥只是更容易被看出）。
- 月牙素材**左右不对称，不能按包围盒居中**。刃口高光与材质刃光的圆心必须取实测弧心（`ARC` 表，`tools/measure_slash.py` 生成），半径取脊线半径。在原点画一个「看起来差不多」的半径，高光会整根悬在图外 —— 实测偏差 40px 以上。
- 专属弧光外面还叠一条**材质色刃光**（`WPN_RIM`）：玉是冷白、青铜是暖金、钝击是土黄、破空是青白。图片负责形状，色线负责在暗背景上一眼分类。
- 弓与四种投掷物**不出手上弧光**（`NO_ARC`）。它们的手上动作是拉弓 / 甩臂，凭空炸一道月牙是错的；特效走弹道 —— `drawProjFx` 把同一张 `WEAPON_FX` 图当速度痕用（箭顺速度拉伸、投掷物在后拖一段残影）。
- 打击火花走 `HIT_MATERIAL`（`jade / bronze / blunt / airy`），由 `WPN_HIT_MAT`（武器 key → 材质）选图，芯色由 `HIT_CORE` / `HIT_MID` 给。它与音频的 `MATERIAL` 是两套表、两种分法：声音要六种配方，画面只要四档。
- 这四类特效图都**不进** `assets.js` 的清单：它们按 `WEAPON_FX[].file` 由 `fx.js` 自建 Image 缓存（首次用到建一次，热路径只读）。`FX.ready()` 也不判它们，逐把走 `weaponFxReady()` / `matHitReady()`，缺图不算致命。

## 投掷物统一管线

- 四种投掷物共用一条管线：`resolveProjectile` 收场 → `explodeProjectile` 范围伤害 → `leaveResidue` 留残骸。
- 手感差异全部交给 `t*` 参数：`tvx` 出手水平速度、`tvy` 出手抬升、`tg` 重力，再加 `pierce / fuse / bounce` 三个专属位。
- 分流靠 `hitSet` 去重：直击过的不再吃爆炸，避免「直击 + 爆炸」重复扣血。
- 经济闭环靠残骸：扔出去 → 落地 → 走回去捡 → 补回一发；不设残骸，投掷物用完就是永久失效。
- 弹数是 `ammo` 不是 `dur`：投掷物的「耐久」语义是剩余发数，上限 5，与近战的挥砍次数分开记。

## 输入与手感

- 键盘与手柄走同一条抽象：每个玩家的输入是一个布尔量集合 —— `left / right / jump / atk / skill / act / drop / give`。「只认四个」是早期版本的说法，拾取与武器动作接进来之后就不成立了。
- 键盘区分「按下瞬间」与「持续按住」；手柄按钮做边沿检测，摇杆做死区判断。
- **一个动作一个键，不允许复用。** 攻击键曾经兼任拾取（键盘侧压根没有独立的 `act` 键，只有手柄 `Y` 有），后果是站在掉落物旁边一按攻击键就先拾取并 `return`，这一刀被吃掉 —— 玩家读到的是「乱拾取」。拾取键拆出来之后，攻击键只负责攻击。
- 新增动作时把键位当资源来分配：先查 `KEYS`、再看 `ui-shell` 独占的 `H / Esc / M / 1 / 2 / 小键盘1,2`，同一玩家内任意两个动作不许共键，两名玩家之间也不许（共用键盘）。
- 攻击输入在挥砍进行中记为「排队」，当前段结束立刻接下一段，这是三连击成立的前提。
- 命中时插入极短停顿（`hitstop`）并把整体 `dt` 压到 8%，这是打击感的主要来源，不要为了「顺滑」删掉。
- 相机跟随两名玩家的中点并做指数逼近；单人时中点就是玩家一。
- 手柄震动的出口统一在 `js/rumble.js`（预设表 + tag→pad 路由，与 `readPad` 同源），是纯反馈层：不支持 dual-rumble 的环境整条链路静默 no-op，游戏状态机对震动零感知。

### 每个可交互界面都必须两条输入都通

这是一条踩过的坑，不是设计洁癖。游戏的 `readPad()` 原先是挂在 `if(G.phase === "play")` 里的 —— 离开对局就再没人读手柄，于是插着手柄的人会卡死在失败页：按钮是 DOM、鼠标点得动、键盘也接了，只有手柄没有路径。

- 判定顺序固定：**先看阶段，再看输入来源**。任何新加的覆盖层都要同时问一句「手柄怎么过这一页”。
- 手柄边沿检测必须带「启用闸」：界面刚打开的那一帧，把玩家送进来的那一下按键还按在手上，直接读按下沿会当场确认掉，玩家连界面都没看见。要求先见到一次全部松开，再接受按下。
- 结算页再加一道时间闸（`CONFIRM_ARM ≈ 0.4s`，与 CSS 淡入对齐），否则最后一刀还按着就把死亡页顶掉了。
- 归别人管的键要显式让开：`H` / `Esc`（按键说明）、`M`（静音）不能被「结算页任意键重来」顺手吃掉。
- 界面文案跟着输入设备走：`body` 上的 `dev-pad` / `dev-kbd` 由 `js/guide.js` 按「**谁在动**」切换（不是「谁插着」——插着手柄但用键盘玩的人，看到的应该是键盘键位）。键位文案与操作图都从 `guide.js` 那四张表来，键盘与手柄两套永不同时出现。
- 对外文档里的键位表也曾写反（写成 `A` 跳 / `X` 挥刀，实际是 `A` 挥刀 / `X` 跳）。键位以 `index.html` 的 `readPad()` 与 `js/guide.js` 的 `PAD_LEGEND` 为准，改哪边都要同步另一处。
- 一帧一写是隐性成本：设备检测每帧都走，`innerHTML` 不能每帧重解析。连接数与设备切换都只在**真的变了**的时候才动 DOM。

### 手机端是同一份代码，不是第二套实现

触屏层独立在 `js/touch.js`，但**游戏本体没有第二份**。手机与桌面跑的是同一套判定、同一套绘制、同一份素材 —— 手机只是把画面缩放，并在屏幕上多画一层虚拟键。

- 独立输入通道，不模拟键盘事件。往 `KEYS` 里塞假按键会顺手把设备判定切成键盘，手机玩家会看到「按 F 挥刀」的提示而屏幕上根本没有键盘。`Touch.state(tag)` 返回与 `readPad()` 同形的对象，`update()` 里用 `||` 并进去。模块缺席时 `tch1` 是 `null`，表达式结果与改动前完全相同。
- 触屏设备判定只看**触摸硬件**（`navigator.maxTouchPoints > 0` 或 `ontouchstart`），不看 `PointerEvent`。桌面浏览器全都支持 PointerEvent，拿它当判据会让鼠标点一下就切进手机版。鼠标与手指靠 `pointerType` 区分（`mouse` 不算手指）。
- 手机版有独立入口 `mobile.html`，它只做一次跳转（带 `?touch=1` 强制触屏档）。**不复制一份 index.html** —— 复制就会漂移，改一处要同步两处，迟早不同步。强制参数存在的原因：从主屏图标启动时没有「第一次手指落下」事件，自动判断会等不到。
- 按键层 `position:fixed` 贴视口，不进 `#stage`（那是 1600×900 逻辑坐标，会被 `transform:scale` 缩到 43px，低于 44px 触摸目标下限）。
- 触屏设备上的 `pointerup` 会丢（来电、切 App、锁屏、手指滑出屏幕）。三道兜底缺一不可：一次性键超时回收、`pointercancel`、失焦三清。方向键不参与超时回收。
- `index.html` 的 script 标签带 `?v=` 版本号：文件名不带 hash，浏览器与 CDN 会长期缓存 `js/*.js`，玩家拿到旧版 `touch.js` 就会在桌面上看到手机虚拟键且刷新不掉。

## 状态机

- 全局阶段：`title → play → clear → play … → win`，任一玩家全灭则 `lose`。
- 敌人状态：`walk → windup → strike → recover → walk`，受击插入 `hurt`，死亡进入 `dead`。
- `windup` 是玩家的唯一预警窗口，`recover` 是 BOSS 的弱点窗口（受伤 ×2）。
- 状态时长写死在敌人构造与转移处，不放在数据文件里：它属于判定，不属于美术。

## 声音

- 打击音全部是代码，没有音频文件。理由不是「不想用素材」，是 `file://` 下 `fetch` / `XHR` 取本地音频会被 CORS 拦 —— 走 `decodeAudioData` 连字节都拿不到。BGM 因此改走**媒体元素**：`<audio src="assets/audio/bgm-main.mp3">` 属于文档子资源，`file://` 直开能播。元素建不出来、报错、文件缺失都退回程序化 BGM，所以「BGM 一定有声」这条不靠素材成立。
- 结构是三层：总线路由（`sfx / music / amb` → 压缩器 → 主增益）、材质打击音、程序化 BGM。压缩器不是可选项，同帧十来个敌人受击线性叠加必然削波。
- 打击音按武器材质分流。青铜的金属感来自**非整数泛音比**（1 : 2.37 : 3.71），整数比会听成音叉；玉与骨不共振，要钝而干；锤是低频土腥（砸进夯土），不是敲铁。
- 打击音的尾层长度由 `G.hitstop` 驱动。画面顿帧 40~75ms 而音频尾巴只有几十毫秒时，视线与听觉的时间尺度不一致，打击就会发软 —— 这两者必须绑在同一个数字上。
- 必须有随机化与复音上限。同参数重复会听觉疲劳，同频同相叠加会让响度忽大忽小；不做节流，双人连打 + 群怪同帧受击会糊成白噪。
- BGM 首选外部音轨 `assets/audio/bgm-main.mp3`（元素播放、循环、`VOL.music × MASTER` 折算音量）。音轨不在时退回 drone / 鼓组 / 旋律动机三层程序化合成，按 `G.waveIdx` 升档，而不是按时间。旋律层必须是**定好的动机**（每档一条五声乐句，32 步一轮），随机拨弦只会听成素材铺底。喘息期把音乐压下去（音轨降到 45%，程序化撤掉节奏层只留 drone），下一阵鼓点回来才有力量；血量见底压一档；BOSS 硬直窗口把音乐让出去，那 0.7 秒属于打击音。**两条路的压音判据必须同口径**，音轨侧在 `mediaLevel()`、程序化侧在 `bgmTick()`。
- 整场响度只有两个总闸：`VOL`（三条总线）与 `MASTER`（总线之后的总增益）。音色配方里的 `gain` 是「相对轻重」的语义，不是音量旋钮 —— 提响度只动这两个，别去改配方表。
- 混响用一根带回授的延时线近似（`file://` 下不想引 ConvolutionIR 素材）。它挂在 music 支路上，老浏览器没有 `createDelay` 就整段跳过。
- 音乐用调式不用大小调：徵调五声（D F G A C）不指向任何具体文化叙事，大小调自带西方「英雄/悲壮」色彩，跟祭祀坑的气场打架。
- 全部声音必须能在没有 `AudioContext` 的环境里安全空转；`js/audio.js` 缺席时内联脚本要退回旧合成器；`Audio` 构造器缺席或音轨加载失败时 BGM 要退回程序化 —— 声音是加分项，不是运行前提，跟三级降级的立场一致。
- 素材换 BGM 只改 `js/audio.js` 顶部的 `MEDIA_SRC` 与 `assets/audio/` 下那份文件，别把 `<audio>` 标签搬进 `index.html`：音量 / 静音 / 喘息压音 / 切后台挂起四条腿全在模块里。

## 防错清单

- 新增素材：先确认降级路径仍在，再确认 `ready()` 判定覆盖它。
- 新增动作：`CLIPS` 预热名单 + `pickClip` 优先级 + `scaleFix`（按内容高反算）三处都要动。
- 新增动作另需：武器到 clip 的映射（需要分流时进 `ATTACK_CLIP`）、切片脚本的 `CHAR_FRAME_RE` 清理正则。
- 新增投掷物：`WEAPONS` 里的 `t*` 参数组 + `TD_COLS` 的爆炸配色 + `DROP_POOL` 的解锁阵次 + `audio.js` 的 `MATERIAL`。
- 每阵专属场景层：`Background.draw()` 末参是阵次（1 起），取图顺序 `bgFar<n>` → `bgFar` → 纯代码。
  **专属层不许进 `CORE_KEYS`** —— 进了就会把「某一阵没出图」升级成「整块背景消失」。
  三层的尺寸被 `background.js` 的几何钉死：远景 1600×900（按宽度等比缩到 `W`）、
  中景宽 1600（原尺寸平铺、底边贴 `GROUND`）、地面宽 1672（高恒等于 `H - GROUND`）。
  换尺寸会让「远景等比、中景原尺寸」这条加宽规则失配，手机加宽后立刻变形。
- 改掉落池：`DROP_POOL` 每件武器一条 `from` / `until`，池内均匀 —— **不许改成加权表**（那张 33 个数字的表删过一次）。`heavyMul` 只放大 `from > 0` 的非基础件。改完跑 `node tools/selftest_drop.mjs`，它的第 5 节会验「条目数即权重」、第 7 节会验「平均伤害只升不降」。
- 奖励只在破阵后出现：小兵一律不掉武器（`hitEnemy` 里只有 BOSS 的三件套），每守住一阵落**一座**宝箱，箱内必给 1 把武器 + 1 件消耗品。整局武器供给从 35.9 把降到 8 把（5 座宝箱 + BOSS 三件套），散落武器从 29.8 把降到 0。要开回「小兵也掉」这条通道，得同步重算宝箱数量与箱内容，否则前中期的武器断供。
- 低伤武器要退场，不是靠权重压小：`until` 是**离散**的，判据是敌人构成（厚甲俑 12 血、BOSS 60 血时 2 伤武器砍不动），不是手感。加新武器时想清楚它该在哪个阵次退场，别让它一路掉到底。
- 后三阵必须各有新武器首次入池，不许第三阵一次开满。现在的排布是锤 / 弓在第三阵、陶罐雷在第四阵、青铜铃在第五阵，对应的都是那一阵的敌人构成与副题；要改就整组一起调，`selftest_drop` 的第 6、7 节会拦住「后半程原地踏步」。
- 新增敌人类型：`ENEMY_ANIM` 键名、`KINDS` 预热名单、血量/速度/体型参数、纯代码降级分支四处都要动。
- 改 `anim-data.js`：任何生成脚本写完都要 `node --check`，历史上这里出过 `fps: 6, true, loop: true` 的语法错误。
- 改背景：`ready()` 现在判 `complete && naturalWidth > 0`，「加载中」与「加载失败」都会让它为假；两者对外都表现为回落纯代码背景。
- 背景是唯一会在 `draw()` 里二次自检的模块：`CORE_KEYS`（远景 / 中景 / 地面）任一不可用就直接返回 `false` 且一像素不画，调用方据此补 `drawBG()`；道具层失败不进这个判定，逐张回落。
- 已知取舍：判定放在绘制之前，所以 `draw()` 返回 `false` 时屏幕上不会留下半张素材背景，调用方可以直接补画，不需要再清屏。
- 新增武器：必须在 `js/audio.js` 的 `MATERIAL` 表里给材质，否则它一律听成玉器；砸锤和玉璋发同一个声音，玩家就感觉不到换了武器。
- 改声音：跑 `node tools/selftest_audio.mjs`。它只证明节点被正确创建与调用，证明不了音色好不好听 —— 配方表改完要人耳听一遍。
- 换刀光素材：先跑 `python tools/measure_slash.py`，把新数值同时填进 `js/fx.js` 的 `ARC` 与 `tools/selftest_weapons.mjs` 的 `ARC_FIXTURE`（5c 会校验两处一致），再看 `convex_dir`：全为 −1 说明仍是「凸背朝左」，`ART_CONVEX` 不用动；出现 +1 就要跟着改。
- 验刀光朝向：`node tools/selftest_weapons.mjs` 的 5b 是唯一自动化防线（14 项断言，改回旧写法当场红）。要人眼复核就用 `tools/probe_slash_orient.py`，但**探针页里不许放文字或辅助线** —— 它们会进像素统计，曾造出 3.4px 的假不对称。
