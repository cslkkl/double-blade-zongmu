## 一句话结论

源画凸背朝左，而要求是**凸背朝人面向的方向** —— 所以面朝右要镜像、面朝左用原样，
与「素材朝右、朝左才镜像」的常规写法相反。旧代码是常规写法，两个朝向都反。

## 验收（实测数字）

- `selftest_weapons`：0 失败；5b 表里 7 组素材全部「面朝右凸背→右 / 面朝左凸背→左 / 对称」。
- 把 `slashMirror` 临时改回 `facing < 0`，自检当场 **14 项失败** —— 防线有效（已实测后还原）。
- 像素探针（900×460 画布，两朝向并排，`_probe_slash.png`）：
  - `facing=+1` 质量重心 `mass_x = +4.61`（锚点右侧 = 身前）；
  - `facing=-1` 质量重心 `mass_x = -5.32`（锚点左侧 = 身前）；
  - 互为镜像偏差 `dx = 0.71, dy = 0.03` —— 在 3px 容差内通过。
- 旧的「亮肚在握柄后方」问题：锚点 `s.x` 本来就在玩家身前 70px，
  月牙质量重心落在锚点前后 ±5px 内，不再整块甩到背后。

## 为什么没改 `index.html` 的纯代码降级弧

`drawSlashes()` 里的降级弧（`a0 = -1.15 + t*1.5`）只在 `FX.ready()` 为假时走，
画的是**径向渐变的环形扇面**，没有左右手性 —— 它不会「反」。
它用 `ctx.scale(s.facing, 1)` 镜像，两个朝向互为镜像，观感一致。
保持现状即可；若将来给它换成有方向的形状，必须一起改。

## 坑（本轮踩到并记下的）

- **`file://` 下 `getImageData` 抛 SecurityError**（canvas 被跨源污染）—— 验像素只能走截图 + 离线分析。
- **截图会超时**：游戏主循环一直在动，Playwright 等不到稳定。要么给 `animations: "disabled"` 并裁剪到目标元素，要么先停 rAF。
- **画布会被全局 CSS 拉伸**：`<canvas width=900 height=460>` 在游戏页里被撑成 1600×900，几何全变形。探针必须显式写 `style.width/height`。
- **探针里的文字标签会污染像素统计**：第一次分析出 3.4px 的「不对称」，`bbox` 上边 −201 正好是标签位置 —— 是装饰不是代码。验几何时别往分析窗里放任何文字或辅助线。
- **mock ctx 的 `save/restore` 必须连绘制状态一起存**（尤其 `globalCompositeOperation`）：只存矩阵时，暖光层设的 `lighter` 会漏给主体绘制，主图被误判成叠加层，测试全红。

## 换素材时必须做的事

1. 重跑 `python tools/measure_slash.py`；
2. 把新数值同时填进 `js/fx.js` 的 `ARC` 与 `tools/selftest_weapons.mjs` 的 `ARC_FIXTURE`；
3. 重跑 `node tools/selftest_weapons.mjs`，5c 会校验两边一致。

若新素材改成「凸背朝右」，`ART_CONVEX` 要改成 `+1` —— `slashMirror` 会整体翻转。
