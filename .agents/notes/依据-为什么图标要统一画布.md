# 依据：为什么图标要统一画布

状态：生效

## 背景

- 拾取物图标是一张拼版图一次出六个（武器 3×2、物品 3×2、界面 2×2），切完每格的透明包围盒大小不同。
- 掉落物在地上一律按「长边 56px」绘制，若各图标按自己的包围盒直接缩放，屏幕上就会忽大忽小：匕首显得比锤子还长，戒指和弓一样大。
- 要确认这个差异有多大，以及归一到什么程度才够。

## 结论

- 直接把六格各裁到包围盒再缩到目标尺寸，等于把「长边」当成唯一标准，短边随各自长宽比浮动；同族内长宽比差异越大，视觉大小差得越远。
- 解法是切完再归一，三步固定：
  - 裁到内容包围盒（去掉切格子时带进来的空白）。
  - 贴进统一的正方形画布。
  - 内容最长边占画布固定比例，居中。
- 归一之后缩放只剩一个自由度（长边），消费侧不再需要知道原始像素尺寸。
- 尺寸档位按用途分：武器 256、物品 192、界面 128；比例系数 0.86 / 0.84 / 0.88。
- 画布越小、档位越紧，是因为界面图标要放进 24px 的 HUD 槽位，留白多一点才不会顶边。
- 实测（alpha > 0 包围盒长边 ÷ 画布边长）：
  - 武器 6 张：全部 0.859（220 / 256），完全一致。
  - 界面 4 张：全部 0.875（112 / 128），完全一致。
  - 物品 6 张：0.411 ~ 0.651，同族内不齐。
- 物品族的数字与脚本设定对不上：`to_uniform(im, 192, 0.84)` 的长边应固定在 161px，磁盘上最大只有 125px。
  - 判定：这批物品图标不是当前这版 [tools/prep_icons.py](../../tools/prep_icons.py) 产出的。
  - 影响有限：长宽比差异本身就在，归一只是把长边钉住；物品族目前只是没钉到 0.84 这个值。
- 副作用：归一会引入缩放，缩放会糊边缘，所以顺序必须是「先抠图去溢色 → 再归一 → 最后压 WebP」，不能反过来。

## 支撑的决策

- 无独立决策记录：这条依据直接体现在 [tools/prep_icons.py](../../tools/prep_icons.py) 与 [docs/ARCHITECTURE.md](../../docs/ARCHITECTURE.md) 的「图标统一画布」一节。

## 影响

- 新增图标必须走 `prep_icons.py`，不能手工裁图直接放进 `assets/icons/`。
- 换生图拼版（行列数、格数变化）要同步改脚本里的 `WEAPONS / ITEMS / ICONS` 名字表与 `split_grid` 的行列参数。
- 想让物品族也对齐到 0.84，重跑一次 `prep_icons.py` 即可；跑完要人眼确认六个物品的相对大小是否合理。
- 若消费侧改成「按原始尺寸绘制」，这条依据即过期。
