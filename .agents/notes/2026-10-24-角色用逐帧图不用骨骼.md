# 决策：角色用逐帧图不用骨骼（2026-10-24）

状态：生效

## 问题

- 角色要有 idle / walk / attack / jump / hurt / whirl / throw / bow / dead 九个动作，得定动画实现路线。
- 参考手感是 4399《双刃战士》那一类，接受「像画出来的」而不是「像摆出来的」。

## 决策

- 路线是 AI 生图出 sprite strip → 脚本切片 → 逐帧播放。
- 帧数据全部落在 [js/anim-data.js](../../js/anim-data.js)：9 动作 32 帧，共用 560×498 画布，字段为 `frames / fps / loop / w / h / anchorX / footY / scaleFix / files`。
- 播放与绘制在 [js/char-rig.js](../../js/char-rig.js)：只读数据、不写数据；`scaleFix` 在绘制时乘进缩放。
- 切片由 `tools/slice_anim.py` 完成（抠图 → 列投影分帧 → 统一锚点 → 预乘缩放 → WebP），它是 `anim-data.js` 的唯一写入口。
- 降级链是 帧图 → `pose0` 单图变换 → 内联 `drawFighter()` 纯代码绘制。

## 替代方案（强制）

- 2D 骨骼动画（拆静态图为部件，代码摆姿势）：素材只有单一姿势，拆件后关节处会散架；而且这类玩法的打击感更吃逐帧硬切，骨骼插值反而滑。
- 纯代码矢量绘制：第一版就是这个（首版提交只有 `drawFighter()`、没有 `js/`），观感被维护者判为太丑，素材帧图接入后即被取代。

## 影响

- 代价：动作质量与一致性完全依赖生图，模型每次画的比例不同，必须靠 `scaleFix` 逐条带校正（当前 0.78~1.49）。
- 代价：换动作等于重跑整条流水线，切片脚本不幂等，会整批重写 `anim-data.js`。
- 收益：帧数据与绘制解耦，重切素材不改一行绘制代码，重做绘制不动一帧素材。
- 收益：动作可逐帧精修，不受骨骼约束与部件接缝限制。
- 只要动作仍由生图条带产出，这条决策就仍成立。
