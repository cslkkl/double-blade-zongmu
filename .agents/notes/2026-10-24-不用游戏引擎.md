# 决策：不用游戏引擎（2026-10-24）

状态：生效

## 问题

- 立项时要定渲染底座：用 Phaser / PixiJS 这类 2D 引擎，还是裸 Canvas 2D。
- 硬性前提是参赛现场断网运行，评审只看「双击 `index.html` 能不能玩」，见 [docs/ARCHITECTURE.md](../../docs/ARCHITECTURE.md)。
- 分发形态只有一个目录，不能要求装环境、不能起本地服务。

## 决策

- 渲染底座是原生 Canvas 2D：一个 `<canvas id="cv" width="1600" height="900">`，主循环走 `requestAnimationFrame`，音效走 Web Audio 实时合成。
- 仓库无 `package.json`、无锁文件、无 `node_modules`、无 `tsconfig.json`；`index.html` 全文无一处 `http` / `cdn` 引用。
- 页面只有 7 条本地 `<script src>` 与 1 段内联 `<script>`，全部 IIFE 挂 `window.*`，见 [js/README.md](../../js/README.md)。
- 相机、碰撞、帧播放、资源加载都是自己写的：`index.html` 三千余行 + `js/` 七个模块四千余行。

## 替代方案（强制）

- Phaser 3（CDN 引入，仓库里没有固定版本号）：CDN 脚本在断网环境直接加载失败，`file://` 下就是白屏；参赛断网是评审硬规则，不是工程偏好。
- PixiJS：同样是 CDN 运行库，同一个断网死因；而且它只解决绘制，不解决「单目录分发」这件事。
- 引入构建工具打包（npm + bundler）：要先装 npm 才能出产物，违背零依赖，评审机也无法保证环境一致。

## 影响

- 代价：引擎自带的相机、碰撞、动画播放、资源管线全部自实现，代码量与自测成本都落在自己身上。
- 代价：没有引擎生态可借用，粒子、缓动、场景切换这类能力只能手写。
- 收益：复制目录即运行，无安装、无版本锁定、无网络请求，评审机一致性由文件系统保证。
- 收益：绘制原语与素材格式完全可控，才有后面的三级降级（素材缺失回落纯代码，任何一张图挂了都不白屏）。
- 若将来允许联网或允许起本地服务，这条决策即失去前提，可重新评估。
