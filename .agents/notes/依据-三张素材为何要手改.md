# 依据：三张素材为何要手改

状态：生效

## 背景

- 生图直接产出的素材不能进游戏，必须过 `tools/` 后处理。
- 这次排查要确认「不能直接用」具体卡在哪几类问题，免得每次重新生图又踩一遍。

## 结论

三类问题，各自对应一道手工处理：

- 洋红底残留：软边像素仍带紫，只做 alpha 抠图不够。
  - 判据是 `min(R,B)-G`：大于 115 直接透明，45~115 按比例降 alpha，见 `tools/prep_assets.py` 的 `key_magenta`。
  - 降完 alpha 还要 despill：把过量的 R / B 压到 `G+34` 以内，再跑 5 遍去污染。
  - 其它脚本各用一档：`prep_fx.py` / `prep_interact.py` 用 `despill=22`，`slice_enemy_anim.py` 更硬。
  - 只抠不压，角色边缘就是一圈紫，缩到显示高度 252px 后更明显。
- 帧条带身高不一致：模型每画一条条带的比例都不同。
  - 9 个动作共用 560×498 画布，但 `scaleFix` 从 0.78 到 1.49 各不相同。
  - walk 的 `scaleFix` 是 1.49、idle 是 1.00，即 walk 条带原始身高只有 idle 的 1/1.49，约小 33%。
  - 所以 `scaleFix` 是校正值不是设计值，换图必须重测。
- 前景层是整图（约 16:9）：草地占近半屏，平铺进游戏像盖了一层黑布，见 `tools/fix_fg_strip.py` 顶部说明。
  - 直接当视差层用，角色会被压在大片深色块后面，遮挡关系也不对。
  - 最终改成拆独立遮挡物：`bgFg` 从 [js/assets.js](../../js/assets.js) 的 `MANIFEST` 移除，改由 [js/background.js](../../js/background.js) 的 `OCCLUDERS` 用道具素材在世界坐标排布（祭旗 / 编钟 / 玉璋碑 / 铜鼎 / 神树）。
  - `assets/bg-fg.webp` 保留在仓里备回滚，不参与加载。

## 影响

- 每次重新生图都要重跑 `tools/` 全流程，不能跳步：`prep_assets` / `prep_fx` / `fix_fg` → `slice_anim` → `slice_enemy_anim`，见 [tools/README.md](../../tools/README.md)。
- 跳过 despill 或跳过统一锚点的产物，验收报表里的「洋红残留」与 `selftest_enemies.mjs` 会对不上。
- 只要素材仍由生图产出，这三类问题就仍成立；换成人工绘制或统一比例图源才会过期。
- `OCCLUDERS` 的 `w / h` 是按素材真实像素比例配准的，换前景素材必须重新配准，否则遮挡框与图对不上。
