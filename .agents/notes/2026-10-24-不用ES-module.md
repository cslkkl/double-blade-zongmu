# 决策：不用 ES module（2026-10-24）

状态：生效

## 问题

- 玩法逻辑要拆成多个 js 文件，得定它们之间怎么互相引用。
- 前提同一条：`file://` 双击运行，不起本地服务。

## 决策

- 全部模块写成 IIFE，执行时把自己挂到 `window.*`，一个模块只暴露一个对象。
- `index.html` 用 7 条平铺 `<script src>` 按固定顺序加载：`assets → anim-data → background → char-rig → enemies-assets → fx`，`ui-shell` 随后。
- 加载顺序就是依赖声明，改顺序即破坏依赖方向，见 [js/README.md](../../js/README.md)。
- 跨模块只通过 `window.XXX` 通信，不共享闭包变量；全仓 `js/*.js` 无 `import` / `export` / `type="module"`。

## 替代方案（强制）

- `type="module"` + `import`：`file://` 下模块请求被当作跨源，浏览器按 `origin null` 拦掉，页面直接白屏。
- 单文件内联：第一版就是这么做的（首版提交 `index.html` 一千七百余行，仓库里还没有 `js/`）；再往里塞 7 个模块共四千余行会失控，也没法单独改一个模块。

## 影响

- 代价：全局命名空间被 `window.*` 填满，重名即覆盖；加载顺序成了隐性契约，靠文档与约束维持。
- 代价：没有 tree-shaking、没有静态检查跨模块引用，导出签名改坏的破坏只能在运行时暴露。
- 收益：零构建、零工具链妥协，双击即跑；改一个模块可直接在浏览器里验证。
- 若将来允许起 http 服务，本条与「不用游戏引擎」一起失效。
