# 依据：手机虚拟键为何用青铜盘与金线纹样

状态：生效

## 背景

- 手机虚拟键原本是**纯 CSS 径向渐变圆钮 + 一个汉字**，与全屏青铜器的画风不搭。
  这一轮要给它换美术，要定的不只是「画什么」，还有几件互相牵制的事：
  - 键面到底放图形还是留文字；
  - 11 把武器换手时，攻击键要不要跟着变；
  - 新素材怎么进仓库（启动期静态图预算已经用满）；
  - 三层素材任何一层缺图时，键会长什么样。
- 硬边界：根 [AGENTS.md](../../AGENTS.md) 写着「每层素材必须有纯代码降级 —— 任何缺图都不许白屏」，
  而按键层是 `position:fixed` 贴视口的独立 DOM 层，一旦某层图挂了就整键消失，玩家会当场没法玩。
- 键的实际尺寸：`vmin` 夹在 `[48px, 84px]`（见
  [docs/手机端适配.md](../../docs/手机端适配.md) 的「六、按键层为什么挂在 `#stage` 外面」），
  小屏横屏上就是 48px 见方。这决定了下文一大半取舍。

## 结论

### 1. 三层：盘（底）+ 暗刻纹样（中）+ 文字（上）

| 层 | 内容 | 职责 |
|---|---|---|
| 底 | 青铜盘：深青绿锈 + 外圈金色云雷纹，中心留空 | 唯一有「实体感」的一层，给出按键边界 |
| 中 | 暗刻金线纹样，**低不透明度** | 只给铸造质感，不承担识别 |
| 上 | 原有文字标签 `◀ ▶ 跳 刀 技 拾 丢 递 ❚❚ ?` | 最终识别兜底 |

三层不是「叠得好看」，是**职责分离**：底解决「这是可点的实体」，中解决「它属于青铜世界」，
上解决「它是什么键」。任一层想兼任另一层，都会在 48px 上失效。

### 2. 文字必须留着，纹样只能暗刻

- 纯图形钮在 48px 上对 `跳 / 技 / 拾` 的辨识度不足 —— 这三个都是单字概念，
  画成纹样之后区分度还不如一个字。文字是这一层里唯一不需要学习的符号。
- 纹样如果全不透明度压上去，会盖住笔画多的 `拾` / `递`；而且金色在深青绿盘上对比度高，
  会先读成「金块 + 暗字」，字反而更糊。
- 所以纹样**只做低不透明度暗刻**（实现是 `opacity:.52`），让位给文字。代价是纹样本身的语义
  （太阳神鸟、太阳轮、玉璧……）玩家基本读不出来 —— 接受，因为它本来就不负责传达功能。
  这个数在 844×390 真机视口上校准过：`.44` 在青绿盘面里几乎看不见（等于白做一层素材），
  `1.0` 跟文字抢读，`.52` 是两者之间那一档。

### 3. 攻击键跟随手上武器

- 手机上最常按的就是这枚键；键面直接给出「我现在拿的是什么」比翻 HUD 快。
  换手在手机上原本**完全没有提示**，这枚键顺带把它变成可见反馈。
- 零新增素材：直接复用 `assets/icons/` 里已有的 10 张（6 武器 `wp-*` + 4 物品 `it-*`，
  其中 `wpRock` 指向 `it-rock.webp`），映射用 `index.html` 的 `WP_ICON` / `wpIconKey()`
  （11 把武器全有声落，`blade→itJade`、`jar→itJar`、`bell→itBell` 三把走物品族），
  路径从 `Assets.MANIFEST` 取。
  这样「新增武器」只有一处要改（`WP_ICON`），不可能出现第二份表与它不同步。
- 空手、或图标还没解码完，键面退回「金线 `atk` 纹样 + 刀字」—— 即空手表现。
- 图标按「武器名」而不是「文件」定缩放：各家留白差得远（`wp-*` 内容占画布 0.859，
  `it-rock` 只有 0.411），同一个尺寸塞进去，石片与玉器会比刀斧小一大圈。
- 目标视觉长边取 `0.62` 而不是 `0.72`：盘的内面只有按钮的约 `0.78`，近方形图标
  （眼形石）在 `0.72` 下会吃满内面、压住盘沿的金纹，读成一坨石头。长条形的刀斧在
  `0.72` 下本来更好，但两者只能共用一个数 —— 取小的，让方形图标留出边框。

### 4. 为什么两种盘

- 动作键用**正圆** `plate`：按键本身就是圆形，盘沿正好贴住按钮边。
- 走键 `◀ ▶`（`.tch-b.dir`）用**圆角方盘** `plate-sq`（`border-radius:26%`）。
  方向键与动作键在屏幕上离得近，形态完全一致会读成「一排同样的键」；
  换成方圆角之后「左边那对是走、右边那堆是打」不用看字。
- 只有这两张盘，没有第三张：再多一种形态就得再解释一次，收益不抵。
- 盘图按 `104.17%`（= `1 / 0.96`）绘制并居中，圆角跟着按钮自身的 `border-radius` 走
  （动作键 50% / 走键 26%），所以两种盘的轮廓都与它所在的键严丝合缝。

### 5. 那圈暗影为什么故意保留

- 盘底下缘的柔和暗影**不抠掉**。盘图自身带圆角（`border-radius` 50% / 26%），
  溢出圆外的暗影被图自己的圆角裁掉，剩下的正好沿盘沿形成一圈接触阴影 ——
  白给的一层立体感，不需要 CSS `box-shadow` 再模拟一遍（`box-shadow` 在 `vmin`
  尺寸下会被非等比缩放拉歪，而且 16 枚键各带一层阴影是实打实的合成开销）。
- 对应代价：**归一化不能按含暗影的 alpha 包围盒**，那个框被暗影撑大一圈，盘体跟着被缩小一圈，
  10 个键的盘会看起来比设计值小。所以归一化取「盘体实心区包围盒」，盘体占画布 0.96。

### 6. 这 10 张图不进 MANIFEST

- 启动期静态图预算已用满：`js/assets.js` 的 `MANIFEST` 现在是 **41 键 / 40 条路径**
  （同名路径共用 `Image`，实测 `Object.keys(MANIFEST).length = 41`、
  去重路径数 = 40），见 [js/README.md](../../js/README.md) 的 `assets.js` 一节。
- 而这 10 张**只有真触屏才用得上**，塞进清单等于让桌面玩家白等 10 次解码与 10 次请求。
- 所以由 `js/touch.js` 自建 Image 缓存，`available()` 为真时才建。
  与 `js/fx.js` 的 `fxImg()`、`js/char-rig.js` 的 `warm()` 是同一套做法：
  「不是所有玩家都要的图，不进启动清单」。

### 7. 被否掉的做法

| 方案 | 否掉的理由 |
|---|---|
| 纯图形钮（去掉文字） | 48px 上 `跳 / 技 / 拾` 分不清；文字是零学习成本的符号 |
| 用 emoji / 系统符号当键面 | 仓库禁外部字体，emoji 字形跨平台不一致，且与青铜风完全不搭 |
| 纹样全不透明度、盖在文字上 | 盖住笔画多的字；金色对比度高会先读成金块 |
| 把纹样直接做成文字（把 `跳` 画成太阳神鸟） | 玩家要先学 8 个映射才能玩，违反「手机上第一次上手就要能用」 |
| 每把武器单独出一张攻击键图 | 11 把 × 1 张 = 11 张新图，且与 `assets/icons/` 那套内容重复；复用既有 10 张零成本 |
| 把这 10 张塞进 `MANIFEST` | 预算已满；桌面玩家为用不上的图付解码代价 |
| 按含暗影的 alpha 包围盒归一 | 暗影撑大包围盒，盘被压小一圈（10 个键一起小） |
| 三层合成一张图（盘 + 纹样烧一块） | 攻击键要换武器图标，烧死之后没法换；也失去逐层降级的能力 |

## 影响

- **改 `WP_ICON` 就要看攻击键**：`index.html` 的 `WP_ICON` / `wpIconKey()` 是武器 → 图标的唯一真源，
  `js/touch.js` 只吃 `iconKey`，不许自己抄一份。新增武器必须同时在这张表里有落点，
  否则那把武器持械时攻击键退回空手的「atk 纹样 + 刀字」（不会出错，但会少一层反馈）。
- **换盘 / 换纹样必须走 `tools/prep_touch.py`**，不能手裁图片直接丢进 `assets/touch/`；
  重跑后要人眼确认两张盘的形状（正圆 / 圆角方）与 8 个纹样是否各自只含一个居中图案。
- **降级链是三层各自独立判**，不是「一层缺就整键退回纯 CSS」。改这段代码时逐层验：
  删 `plate.webp` → 退回径向渐变圆钮；删某个 `glyph-*` → 该键只剩文字；`setWeapon(tag, null)` →
  攻击键回到 `atk` 纹样 + 刀字。三种情况都不许出现透明键或白屏。
- **素材不进 `MANIFEST`，所以 `showcase.js` 得手写清单**（浏览器不能列目录）。
  删图不删 `TOUCH` 表里的行，展示页就是 404 空框；这条与本仓其它手写清单同一个坑。
- 若哪天虚拟键改成 canvas 绘制、或图标改由另一条渲染路径提供，本文的「三层」「不进 MANIFEST」
  两条即过期；「文字是兜底」「纹样只做暗刻」与实现无关，仍成立。
